# Plan: an editor of the river network in „Sieć i trasowanie”, after HEC-HMS

Approved: pending

Requested by the author on 2026-11-10: a graphical editor of the network in the GUI, modelled on the basin model editor of HEC-HMS, in which the person adds elements, connects each to the element below it and describes each one (its id, a description, its parameters). Today „Sieć i trasowanie” opens a network from a file, a hand-off or the guide's example, draws it from `route schematic` and edits the parameters of its nodes; the structure is shown and never edited (the GUI plan's D18 and S4). This plan supersedes those two points; the rest of [2026-11-02-hydrolog-gui.md](2026-11-02-hydrolog-gui.md) stands. It is on the branch `plan/network-editor` from `develop` `759d7ef`. The decisions below are the agent's, for the author's review; each open question at the end has a recommended answer.

Requirements: DEV-17.4 (a change of the public documents `hydrolog-network/1` and `hydrolog-network-schematic/1` starts with a plan), DOC-8.1 (ADR-0023), AGI-4.1 (optional fields keep the version), DEV-15.1 to DEV-15.3, DEV-2.3 (Polish texts through the label modules; the Polish-only deviation from DEV-2.2 in `CLAUDE.md` stands), DOC-7.2, HUB-5.2 (D4: no project but Hydrolog changes). Inputs: [ADR-0010](../decisions/0010-route-network-document-and-output-directory.md), [ADR-0012](../decisions/0012-network-objects-rainfall-and-runoff.md), [ADR-0013](../decisions/0013-network-schematic.md), [ADR-0014](../decisions/0014-web-gui-enters-the-scope.md); the GUI plan (D8, D9, D12, D16, D17, D18, S4); Nogat's `design/README.md` (WCAG 2.2 AA contrast, never colour alone, the focus ring); the HEC-HMS User's Manual ([source, junction, diversion and sink elements][hms-elements], [reach elements][hms-reach]). No code before `Approved:`.

## Goal

- Build a network on the canvas of „Sieć i trasowanie” as in HEC-HMS: an element palette, placing and moving elements, connecting an element to the one below it by dragging, deleting elements and links, renaming, describing, the parameters in the existing node form, undo and redo. Every action also works by keyboard, by a single pointer without dragging, and as ordinary form controls in „Dane”.
- Start empty, from a file or from a Hydrograf hand-off, add the subcatchment of a hand-off to an open network, and save the document.
- Check the structure while the person edits, with the library's reason codes (`cycle`, `upstream_count`, `no_outlet`…) marked on the canvas, and let Hydrolog confirm every complete network.
- The document keeps the picture: an optional `position` and `description` per node in `hydrolog-network/1`. The library draws the person's positions (`RoutingNetwork.schematic()`, `route network --schematic`), so the SVG and the report show what the canvas shows; a document without positions gets ADR-0013's layout, which „Uporządkuj” also restores.
- Hydrolog still computes every value. The browser draws, keeps the cells the person chose and checks the structure rules for immediate feedback (D8).

## Decisions

### D1. Sieć becomes the editor

No new section and no mode switch: the card „Schemat sieci” in the centre is the canvas and is editable at once. „Tabela węzłów” stays as the other view, with the columns „Opis” and „Odpływa do”. A click on a node still chooses it (its settings in „Dane”, its result in „Wyniki”); a press that moves less than 4 px is a click, a longer one a drag. The GUI plan's D18 point „the network's structure … is not edited” and S4's „the structure is shown, not edited” are superseded; E3 adds the erratum to that plan. The canvas replaces `schematic-view.js` and the transform of a schematic document in `schematic.js`: nothing in the page draws from `route schematic` any more (D5, D8).

### D2. Elements: Hydrolog's five types, and HEC-HMS's other three

| HEC-HMS | Hydrolog | Note |
|---|---|---|
| Subbasin | „Zlewnia” (`subcatchment`) | makes its hydrograph from `watershed`, `runoff` and `rainfall`, or is given it |
| Reach | „Odcinek” (`reach`) | lag, Muskingum, Muskingum-Cunge, cascade or level pool. A HEC-HMS reach takes one or more inflows ([reach elements][hms-reach]); Hydrolog's reach, reservoir and outlet take exactly one and only a junction adds (`upstream_count`), so a second inflow into them offers „Wstaw złącze” (D7, Q7) |
| Reservoir | „Zbiornik” (`reservoir`) | level pool with a storage–outflow table, inline or as `rating_file` |
| Junction | „Złącze” (`junction`) | adds its inflows |
| Sink | „Wylot” (`outlet`) | exactly one per network (`no_outlet`, `several_outlets`); HEC-HMS permits more than one outlet in a basin model |
| Source | none of its own | HEC-HMS's source adds „measured inflows … or upstream boundary conditions” ([elements][hms-elements]). In Hydrolog that is a subcatchment given its hydrograph (variant „Podany”: `times_min` and `discharge_m3s`) or reading its column of the inflows file (variant „Z pliku”). The palette's „Zlewnia” says so in its hint; a type of its own would repeat the subcatchment's variants |
| Diversion | none | HEC-HMS's diversion is where „water is withdrawn from the channel, and may be discharged to a canal or stream” ([elements][hms-elements]): a node with two outflows. ADR-0010 refuses a node that flows into two (`several_downstream`: a lumped model would count its water twice), and ADR-0013's picture is a drawing of a tree. A diversion needs a node type with a split rule, a network that is no longer a tree (the order, the balance, the schematic) and links that say which outflow they carry: a plan and an ADR of its own. A withdrawal whose water leaves the network has one outflow and would fit as a registered node type (ADR-0012); it is left out too |

The palette has five buttons, each with its kind's glyph and Polish name as in the legend. A new element gets the id `Z1`, `R1`, `ZB1` or `J1` with the first free number, and the outlet `OUT` (the ids of Hydrograf's hand-off and of the guide's example); the person renames it at will. A second outlet can be placed while editing and is marked (`several_outlets`).

### D3. The document: `description` and `position` in `hydrolog-network/1`

- Per node, both optional:
  - `description`: plain text of 1 to 500 characters (Q3) without control characters other than the line feed (they are not valid in the SVG), never read as HTML or Markdown. Reasons: `type`, `empty` (blank), `too_long` (`details.max_length`), `control_character`.
  - `position`: `{"x": …, "y": …}`, the cell of the node in ADR-0013's grid (`x` grows downstream, `y` sideways; the canvas shows `x` downwards), integers from −1000 to 1000, these two keys only. Reasons: `type`, `unknown_field`, `missing_field` (`field` `position.x`), `minimum`, `maximum`.
- Neither changes a computation: the result, the tables and `describe()` are the same with and without them, byte for byte (D13).
- The canonical form writes them after the fields of the kind, `description` then `position`, and only when given; a document without them is written as today.
- If the author agrees (Q3), the network gets the same optional `description` at its top.
- The version stays `/1` (AGI-4.1, as ADR-0012 did); a `/2` would break Retman's recognition (the exact `schema`) and Hydrograf's payload for a change that alters no meaning. A Hydrolog older than E1 refuses a document that has the new fields (`unknown_field`), as every Hydrolog before ADR-0012 refused `watershed`; older documents read as before everywhere. The reader stays strict (ADR-0010): a misspelt field is still an error, not something ignored.

### D4. The library and the consumers

- `Node` gains `description` and `position` (a `Position(x, y)` exported from `hydrolog.routing`) and the copies `with_description()` and `with_position()`, like `with_inflows()`, which check the values with D3's reasons and `details.node_id`. They live on the base class and are read and written in one place (`Node.read_entry`, `Node.to_document`; `_COMMON` of `routing/network.py` and of `operations/_network_input.py`), so every registered type, one from another package too, carries them without code of its own.
- `RoutingNetwork.from_document` and `to_document`, `read_network` and `write_network` keep them; `route network`, `route schematic` and the MCP tools read them. No catalog option changes, so `AGENTS.md` and `llms.txt` stay; the JSON Schema of `/1` is regenerated with both properties in every node branch. The result `hydrolog-route-network/1` and `ControlPointNetwork` do not change. `hydrolog.testing` keeps in step with the format (DEV-10.6: Retman reads these files): `placed(node, *, description=None, position=None)` adds the fields to a node of its builders, and `network_document` checks them through the real loader.
- HUB-5.2: Hydrolog owns the document and the change is additive. Hydrograf keeps writing `/1` hand-offs without the fields, and its test against the schema keeps passing. Retman keeps recognising the file and reads the fields once its release set takes a Hydrolog with E1. A hand-off written by Sieć may carry the fields; only Hydrolog reads such hand-offs today (Hydrograf reads none until the platform's step 12). No other project has to change, so no Nogat plan is needed. After E1 lands, Nogat's registry entry of `hydrolog-network/1` in `ecosystem.yaml` may name the optional positions and descriptions, on Nogat's own branch (producers first).

### D5. The picture of a placed network

- `RoutingNetwork.schematic()`, and with it `route network --schematic` and `route schematic`, takes the positions when every node has one and no two share a cell. The nodes stay where the person put them, moved together so that the smallest `x` and `y` are 0. The lines (colours, the main stem) are ranked as before, `main_stem` included, and the labels follow ADR-0013's rule.
- Rule D draws the edge from node A to the node B it flows into, with `dx` and `dy` the steps from A to B in grid units:
  1. `dx = 0` or `dy = 0`: one straight segment.
  2. `dx > 0`: a sideways leg of `|dy| − 1` to the row next to B's, one 45° step onto B's row, then along that row into B (`dx − 1`); a leg of length 0 is left out. This is ADR-0013's join (the vertical leg, 45 degrees, the taps along the line), and it equals every edge of the computed layout (Where it starts).
  3. `dx < 0` (B upstream of A, which a person may arrange): a 45° leg of `min(|dx|, |dy|)` from A, then straight into B.

  Every segment stays at 0, 45 or 90 degrees. A placed picture may cross itself, which the computed one never does: that is the person's arrangement. The canvas marks an edge that runs through another node as a hint (not a problem: Hydrolog draws it as placed), and „Uporządkuj” restores ADR-0013's picture.
- A document with positions on some nodes only, or with two nodes on one cell, gets the computed layout, and `route network` and `route schematic` add the warning `positions_ignored` (`details.reason` `partial` or `shared_cell`, `node_id`). The code goes into `NOTICES` with its Polish text (GUI plan D16).
- `hydrolog-network-schematic/1` gains two optional fields and keeps its version (AGI-4.1): `layout` (`given` or `computed`) and the `description` of a node; its description says that a given layout may cross. `schematic_svg` adds the description to the node's tooltip.
- ADR-0023 amends ADR-0013: the picture now depends on the network and on the positions its document holds.

### D6. The canvas: inline SVG with Pointer Events, an own module

The canvas grows from what Sieć draws today: inline SVG (`sections/siec/editor/canvas.js`) with the glyphs, classes and tokens of `schematic-view.js`. A node is a focusable `<g>` with its ARIA, edges follow rule D, and the grid is turned as in `schematic.js`. Dragging uses Pointer Events with `setPointerCapture`, as the panel resizer does: one set of listeners on the SVG, the 4 px threshold, the dragged node's group moved by its `transform` attribute while the pointer moves, and the edit committed on release. Nothing sets a `style` attribute, so `style-src 'self'` holds; the canvas's classes live in `app.css`. Zoom changes the `viewBox`; the canvas scrolls natively, which keyboards and assistive technology already handle. The pure parts (`geometry.js`, `graph.js`, `edits.js`, `history.js`) use neither Preact nor the DOM, so Nogat's kit can wrap them as the GUI plan's D9 intends for `schematic.js`. No file is vendored, and the server and its private API do not change (GUI plan D5).

Rejected:

- A diagram library (JointJS, Drawflow; React Flow and Svelte Flow need their frameworks and a bundler): a second visual language beside the tokens; built for the mouse, so the keyboard model of D12 would be ours anyway; generic ports where Hydrolog has one downstream link per node; and the bare imports of the ES-module builds need an import map, an inline script that `script-src 'self'` refuses, or a rewritten import in every vendored file (the GUI rewrote one, in Preact's hooks; GUI plan D9).
- Cytoscape.js and other renderers on a `<canvas>`: no element per node to focus, name or test, and PNG and print want SVG (the GUI plan's reason against Chart.js, D12).
- d3-drag and d3-zoom: little beyond Pointer Events and a `viewBox`, as several modules with bare imports.

### D7. Interactions

| Action | Pointer | Keyboard, canvas focused | Single pointer, no drag | „Dane” |
|---|---|---|---|---|
| choose a node | click | arrows: the nearest node in that direction; Enter or Space opens it | click | the node list (step 2) |
| add an element | drag from the palette to a cell | `D` on a node: „Dodaj dopływ”, the palette as a menu | click a palette item, then a cell | „Dodaj węzeł” (step 2), placed next to the chosen node |
| move | drag to a cell (snapped; a taken cell refuses the drop) | Shift+arrows: one cell | „Przesuń”, then a cell | – |
| connect A to B | drag from A's handle (the dot on its downstream side) onto B | `P` on A, arrows among the allowed targets, Enter | „Połącz z…”, then B | „Odpływa do” (step 3) |
| disconnect | click the link, Delete | `O` on A | „Odłącz” | „Odpływa do: brak” |
| delete a node | node menu | Delete | „Usuń” | „Usuń węzeł” (step 3) |
| rename | node menu | F2: the id field in „Dane” | „Zmień id” | the id field (step 3) |
| describe | – | – | – | „Opis” (step 3) |
| parameters | – | Enter | – | the existing form (step 3) |
| undo, redo | „Cofnij”, „Ponów” | Ctrl+Z; Ctrl+Shift+Z or Ctrl+Y | the same buttons | – |
| tidy | „Uporządkuj” | – | the same button | – |
| zoom | „−”, „+”, „Dopasuj” (the wheel and Ctrl+wheel keep scrolling and zooming the page) | `+`, `−` | the same buttons | – |
| node menu | right click, long press | Shift+F10 or the Menu key | „Węzeł…” in the toolbar | – |

The toolbar sits in the head of the card: the palette, „Cofnij”, „Ponów”, „Uporządkuj”, the zoom, „Węzeł…” (the menu of the chosen node) and „Skróty” (the keys, also on `?`).

- **Adding.** `D` places the new element in the free cell above the focused node and connects it into that node; a node that takes no more inflows refuses with the reason. From the toolbar or with nothing chosen, the element is placed unconnected.
- **Connecting** sets A's one downstream link; a link that A had moves to B and the live region says so. At the drop, and while the drag hovers B, the editor refuses a cycle (`cycle`), an inflow into a subcatchment (`upstream_count`) and a link out of the outlet (`outlet_has_downstream`), with the reason. A second inflow into a reach, a reservoir or the outlet offers „Wstaw złącze” (a junction in the free cell above B takes both inflows and flows into B; one step to undo) or „Anuluj” (Q7). A bifurcation therefore never comes from the editor, only from a file.
- **Deleting** removes the node and its links. „Usuń i połącz”, offered for a node with one inflow and a downstream link, links that inflow to the downstream node instead.
- **Renaming** checks the id as it is typed, as the library does: the pattern and length, the device names of Windows, and uniqueness without regard to case (`invalid_id`, `reserved_name`, `duplicate_node`). On commit every `from` that names the node follows. A subcatchment that reads its column of the inflows file by its id keeps that column: `value_column` takes the old id, and the note says so.
- **Staleness.** A structural edit or a rename marks the result stale, a move or a description never does (D11).

### D8. Live validation on the canvas

1. **Fields**, unchanged: `node-model.js` checks every value against the schema; a node with a problem carries the mark of point 4.
2. **Structure**, in the browser (`editor/graph.js`), synchronously after every edit, with ADR-0010's reasons and the library's codes, every problem at once: `empty`, `invalid_id`, `reserved_name`, `duplicate_node`, `unknown_upstream`, `duplicate_upstream`, `upstream_count`, `several_downstream`, `cycle` (its nodes in flow order), `no_outlet`, `several_outlets`, `outlet_has_downstream` and `disconnected_node`. The inflow counts come from the `from` bounds of the schema. The edits of D7 never make `unknown_upstream`, `duplicate_upstream` or `several_downstream`; an opened file can, so they are checked too. A test runs a corpus of one-problem documents through this module and through `RoutingNetwork.from_document`: the library's `details.reason` and `node_id` must be in the browser's list (D13).
3. **Hydrolog**: once points 1 and 2 find nothing and the files are present, `route schematic` runs on its own channel 300 ms after the last change, as today. Its error marks its node with the Polish text of its reason; its picture is not used.
4. **Display.** A node with a problem gets a mark „!” in the error colour beside its glyph, and the problem stands in its tooltip and accessible description (never colour alone). The links of a cycle are dashed. A list „Problemy sieci (n)” above the canvas names every problem, and each item chooses its node; the network-wide ones (`empty`, `no_outlet`, `several_outlets`) appear in the list only. The status badge works as today („Dane niepełne: …”). A link being dragged shows its verdict on the target before the drop: „✓” or „⊘” with the reason in the live region.

### D9. Undo and redo

The history holds the section's inputs (`network`, `skeleton`, `nodes`), up to 100 steps, in memory only. A reload keeps the network, as today, but not its history; opening or clearing a network starts a new one. Each action is one step: a drag is one step, moves of one node by keys within 1 s are one, and a parameter is one step when its field commits (`change`), not per key. The inputs are immutable and share their unchanged nodes, so a step costs only the nodes it changed. The shortcuts act while the focus is in the canvas or its toolbar; in a text field the browser's own undo stays.

### D10. Starting, opening, saving

- **Empty.** „Nowa sieć” in step 1 (beside „Plik sieci…” and „Wczytaj z Hydrografa”) opens an empty canvas with the palette and a hint.
- **File.** As today (`documentProblems`, the companion files, `withSessionNames`). A document with positions opens as placed. Without them, the editor asks Hydrolog for the layout (`route schematic`) as soon as the library can read the network and stores the positions; this is part of opening, not a step to undo. A network the library cannot read yet (incomplete or broken) is placed in rows by its longest distance from a headwater and marked „Układ tymczasowy” until „Uporządkuj” works. A node without a position, or on a taken cell, goes to the nearest free cell; an invalid position is dropped and its node placed; a note names them.
- **Hand-off.** „Wczytaj z Hydrografa” in Sieć opens a network hand-off in Sieć even when it holds one subcatchment; the same button elsewhere still routes by `targetOf`. With a network open, „Dodaj zlewnię z Hydrografa” adds the hand-off's subcatchments: renamed when the id is taken (`Z1` becomes `Z2`), without the hand-off's outlet, with the subject as the description, in free cells of the top row. A different `timestep_min` keeps the network's and says so. A subcatchment's own `rainfall` comes with it, and a rainfall at the hand-off's top becomes the node's own when the network's differs.
- **Stored inputs.** The section keeps its inputs in `localStorage` as today, now with positions and descriptions.
- **Saving.** „Zapisz sieć” downloads the document with positions and descriptions. An incomplete network (Q5) is saved by „Zapisz szkic”, the same file: the toast says that `route network` refuses it until the listed problems are fixed, and the GUI reopens it.
- **Discarding.** „Wyczyść” and „Nowa sieć” ask first when the network changed since it was opened or saved (PROGRESS, Next 8).

### D11. Results, staleness, exports

- The key that marks a result stale leaves out `position` and `description`.
- The document sent to `route network` carries both, so its `--schematic` draws the person's picture.
- The PNG is the canvas without the marks of editing: handles, selection and problem marks are hidden by a class while `toPng` copies it.
- The hand-off written from Sieć carries the document as it is.

### D12. Accessibility

The editor meets WCAG 2.2 AA, the level of Nogat's identity:

- **Keyboard (2.1.1).** Every action of D7 has its keys. The single-character shortcuts (`D`, `P`, `O`, `+`, `−`, `?`) act only while the canvas has the focus (2.1.4), and „Skróty” lists them.
- **Dragging (2.5.7).** Every drag has a single-pointer way (D7).
- **Targets (2.5.8).** A node's hit area is its 40 px halo; handles and the hit lines of links are at least 24 px.
- **Focus (2.4.7, 2.4.11).** The focus ring of a node is its halo; the focused node is scrolled into view, not under the toolbar.
- **Colour (1.4.1, 1.4.11).** A problem is „!” with text, a refused drop „⊘” with text, the chosen node the halo with `aria-pressed`; the marks reach 3:1 in both themes.
- **Names and messages (4.1.2, 4.1.3).** Nodes are buttons named by id, kind, description and problems. A polite live region announces each edit and each refusal („Połączono Z1 → R1”, „Nie można: pętla Z1 → R1 → Z1”), and the canvas names its keys in `aria-describedby`.
- **Screen readers.** Every structural edit is also an ordinary form control in „Dane” (D7).
- **Motion.** With `prefers-reduced-motion` nothing moves by animation.
- **Phones (390 px).** The palette becomes a menu „Dodaj element”; moves and links also go through the node menu and „Odpływa do”. Nodes take touch drags (`touch-action: none` on the node class) and the empty canvas scrolls.

### D15. A later stage: the background map

HEC-HMS shows a map of the basin behind its elements. It is not in this plan. In Hydrolog it would need:

- a location per node in geographic coordinates (e.g. an optional `location` with WGS84 `lon` and `lat`), separate from `position`, so that the schematic stays a schematic; Hydrograf's provenance already carries the point of an outlet;
- a basemap: tiles from an origin that the CSP has to allow (`img-src`, `connect-src`), with its attribution; Nogat's platform plan gives its kit a `basemaps.json` of shared basemaps, attributions and the origins a CSP must allow;
- a vendored map library, or Hydrograf's map;
- the boundaries of the subcatchments and the streams, which only Hydrograf has: Hydrolog has no spatial data ([SCOPE.md](../SCOPE.md)).

Recommended (Q8): the map belongs to Hydrograf, whose control points (the platform's step 18: the outlet first, a `hydrolog-network/1` of residual subcatchments, the schematic beside the map) produce the network, which the hand-off brings to this editor. A map in Hydrolog's GUI would be a plan and an ADR of its own.

## Risks

| Risk | Effect | Mitigation |
|---|---|---|
| A Hydrolog older than E1 reads a file that the new GUI saved | `unknown_field` in a consumer that pins it | additive within `/1`, as ADR-0012 did; the release sets move the consumers' pins together; today only Hydrolog reads these files |
| The browser's structure check drifts from the library's | the canvas says valid and Hydrolog refuses, or the reverse | the one-problem corpus through both (D13); the library checks every complete network (D8, point 3); where JavaScript's lower case differs from Python's `casefold` (ß), point 3 still refuses |
| Rule D drifts between the browser and the library | the SVG differs from the canvas | the parity test and the property test against the layout (D13) |
| A placed picture crosses itself or an edge runs through a node | an ambiguous picture | the person's arrangement: the canvas marks an edge that runs through a node as a hint, and „Uporządkuj” |
| Pointer handling on touch screens | drags that scroll or select text | Pointer Events with capture, `touch-action` by class, the menu and „Odpływa do” as other ways; the 390 px tests |
| Large networks (hundreds of control points from Hydrograf) | slow drags | during a drag only the node's group moves by its `transform`; the inputs change on release; the 300-node smoke of E2 |

## Open questions for the author

1. **Placement**: snapped to ADR-0013's grid, or free? Recommended: snapped. Free placement needs fractional positions and another edge rule, the computed picture could no longer be stored exactly, and the keys would move by an arbitrary step.
2. **Version**: optional fields in `hydrolog-network/1`, or `hydrolog-network/2`? Recommended: `/1` (AGI-4.1, ADR-0012's precedent); a `/2` breaks Retman's recognition and Hydrograf's payload for nothing that changes a meaning.
3. **Descriptions**: plain text of up to 500 characters, line breaks allowed, no Markdown; and the same `description` for the network at its top? Recommended: yes to both.
4. **Names**: is the id the element's name, as in HEC-HMS (letters with Polish diacritics, digits, `_`, `.`, `-`, no spaces), or does a node get a display name besides it? Recommended: the id; the description holds any other words.
5. **An incomplete network**: save it as „Zapisz szkic”, or save complete networks only? Recommended: the draft. Nothing is lost, `route network` refuses the file with the first missing value named, and the GUI reopens it.
6. **„Uporządkuj” before every parameter is given**: recommended not in this plan. The layout needs a network that the library can read, and the person places the nodes meanwhile. The alternative is a `route schematic` option that lays out the structure alone: a catalog option, an amendment of ADR-0013 and a `timestep_min` that such a schematic cannot know.
7. **A second inflow into a reach, a reservoir or the outlet**: offer „Wstaw złącze”, or only refuse with the reason? Recommended: offer it; HEC-HMS users expect a reach to take several inflows.
8. **The background map**: in Hydrograf, on its control points, or in a later stage of Hydrolog (D15)? Recommended: Hydrograf.

## Not in this plan

The background map (D15); a layout of the structure alone (Q6); diversions and withdrawals (D2); choosing several nodes, copying and pasting, moving groups; a display name besides the id (Q4); bends stored in the document; an English UI; the editor in Nogat's kit (the platform's `<nogat-schematic>` takes the pure modules later); Hydrograf reading Hydrolog's hand-off (the platform's step 12).
